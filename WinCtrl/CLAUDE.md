# WinCtrl: 측창 모터 제어기 펌웨어

ESP32-S3(N16R8) 한 대로 비닐하우스 측창 모터 2대를 초 단위로 여닫는 제어기의 펌웨어다.
설계와 결정은 claude.ai 프로젝트 "비닐하우스 개폐기 제어기"에서 해 왔고, 그 결과는 아래 문서에 있다.

## 기준 문서 (Google 드라이브 "측창 모터 제어기" 폴더)

작업 전에 먼저 읽고 따른다. 코드와 문서가 다르면 문서가 기준이다.

- 소프트웨어 스펙 v0.9: https://docs.google.com/document/d/1h4CePoZDpxb1MbhL4dKiL9WRhA8tGXZF1WrzBWJW2RQ/edit
- 핀 배정 (ESP32-S3): https://docs.google.com/document/d/1T1Guv7jlq9PdXkdR1XEOk0o6jumPseRxq5PzQkQtSgs/edit
- 설계 정리 (2채널 50W/300W): https://docs.google.com/document/d/1Ofmi7evdES44NVbZpK2k-cxzMU7yUX5PIwzKwpirTas/edit

문서를 읽을 수 없으면 사용자에게 내용을 붙여 달라고 한다. 스펙에 없는 동작을 정해야 하면 혼자 정하지 말고 사용자에게 묻고, 정해진 내용은 문서에 반영하도록 알린다. 문서의 사본을 저장소에 만들지 않는다.

## 개발 환경

- 맥 + VS Code + PlatformIO. 이 폴더(`WinCtrl`)를 열어야 `platformio.ini`가 인식된다. 아두이노 IDE로도 열린다 (README 참고).
- 업로드와 시리얼은 보드의 COM(UART) 포트, 115200bps. USB 라벨 포트(직결 USB)는 쓰지 않는다.
- USB 허브를 거치면 보드가 안 보인 적이 있다. 맥에 바로 꽂는다.

## 구조와 규칙 (스펙 2~4절)

- 네 층: 1 장치(`dev_*`), 2 제어(`ctl_*`), 3 조정(`app_*`), 4 입력(`io_*`). 의존은 위에서 아래로만, 층을 건너뛰지 않는다.
- 핀 번호와 하드웨어 함수는 1층에만 둔다. 핀은 `pins.h`, 상수는 `config.h`.
- 태스크 2개: 제어(코어 1, 10ms 고정)와 화면(코어 0, 약 20ms). 모터, MC, 창 상태는 제어 태스크만, LCD, 소리, 플래시 저장은 화면 태스크만 만진다.
- 시간과 위치는 0.01초 = 1인 정수(`cs_t`). float를 쓰지 않는다. 전류는 mA, 출력은 천분율.
- 창 상태 흐름은 enum 하나와 switch 하나. 상태 바꾸기는 `setState()` 한 곳에서만 한다. State 패턴(상태별 클래스)은 쓰지 않기로 했다.
- 안전 판정(스펙 6절)은 상태와 상관없이 상태 흐름보다 먼저 하고, 어떤 경로로도 건너뛸 수 없게 둔다. 안전 규칙을 약하게 바꾸는 변경은 사용자에게 먼저 확인한다.
- 모델 구분: GPIO39 점퍼가 열림(HIGH)이면 300W, GND면 50W. 점퍼가 빠져도 과부하를 놓치지 않도록 기본을 300W로 정했다. 바꾸지 않는다.

## 확인 방법

```
sh test/run_tests.sh       # 2층, 3층, 화면 글자를 PC에서 시험
sh test/check_compile.sh   # 아두이노 쪽 파일을 가짜 헤더(test/stubs)로 문법 확인
```

코드를 고치면 둘 다 통과시킨다. 아두이노 함수를 새로 쓰면 `test/stubs`에도 넣는다. 실제 확인은 PlatformIO 빌드와 보드 업로드로 한다.

## 책상 시험 메모 (2026-10-16 확인)

- 빌드, 업로드, 50W 점퍼, 엔코더, I2C 화면은 동작을 확인했다.
- 시리얼 로그: 부팅 시 버전, 모델, I2C 선 상태와 장치 주소. 5초마다 `[alive]`와 엔코더 핀 상태. 엔코더 회전과 누름은 `[enc]`.
- 1602 LCD의 I2C 모듈은 전원을 거꾸로 넣어 망가졌다. LCD가 없으면 I2C OLED(SSD1306/SH1106, 0x3C/0x3D)에 같은 두 줄을 그린다 (시험용 대체 화면).
- 24V 회로가 없으면 E-STOP이 걸린다. GPIO1을 3V3에 이으면 풀린다. GPIO6(MC 뒤 전압)은 떠 있으면 MC 에러가 날 수 있어 10kΩ으로 GND에 잇는다.
- 엔코더 방향은 `config.h`의 `ENC_DIRECTION`. 지금 시험 모듈(S1/S2 표기) 기준 -1이고, PEC16을 달면 다시 확인한다.
- 제어 태스크가 읽는 아날로그 핀을 다른 태스크에서 같이 읽지 않는다.

## PCB 시험 메모 (2026-11-18, 첫 납땜 PCB)

- 시험 펌웨어는 `pio run -e test_pcb -t upload` (`hwtest/test_pcb.cpp`, README "PCB 시험"). 출력 핀은 LOW로 두고, 모터2만 `u`/`d` 명령으로 1초 돌린다.
- 확인함: 출력 핀 8개 붙음 없음, 아날로그 5핀 GND 쪽 저항, S1/S2/엔코더/모델 점퍼 풀업, I2C와 1602 LCD(0x27), 피에조 GPIO38, 엔코더 회전과 누름(방향 `ENC_DIRECTION` -1 그대로 맞음), 모터 드라이버 2번 연결 후 M2 핀.
- PCB의 5V(LCD 전원)는 24V에서 만든다. CPU 보드는 USB 5V와 충돌하지 않게 5V를 밖으로 내보내지 않으므로, USB만 꽂으면 LCD가 꺼져 있다. 24V 쪽 5V와 USB 5V가 충돌하지 않는 것을 확인했고, 지금은 24V와 USB를 같이 꽂고 시험한다.
- 엔코더 모듈의 풀업 저항이 메인 보드 풀업과 겹쳐 떼어 냈다. 그때 핀헤더와 A, B를 잇는 부품까지 같이 떨어져 회전이 안 잡혔고, 다시 이어서 해결했다.
- 2026-11-19: 온도 센서(PT100 변환기 0~50°C)와 모터2(24V 62W, 정격 약 2.5A, 책상 위 축 자유)를 달았다. MC 없이 24V를 드라이버에 바로 넣었다.
- 모터2 상승(RPWM)과 하강(LPWM) 모두 돈다. 3×3 점퍼(JP2) 캡이 빠진 채 300W(817Ω)로 환산해 전류가 약 2.7배 크게 읽혔다 (100%에서 5.5A). 세 줄 모두 50W로 꽂은 뒤 30/50/70/100% 1초 평균은 상승 90/274/475/767mA, 하강 54/191/355/608mA로 앞의 값의 약 1/2.7이 되어 저항 전환은 맞다. 최고는 소프트 스타트 끝(100%에서 상승 2.3A, 하강 2.0A).
- 축이 자유인데도 상승(RPWM)이 하강(LPWM)보다 크게 읽힌다. 100% 3초에서 0.6초 뒤 평균 732mA/553mA (약 1.33배). 모터 선을 바꿔 물려도 RPWM 726mA, LPWM 566mA로 그대로라 모터가 아니라 드라이버 두 반쪽(R_IS, L_IS)의 KILIS 차이로 본다. 방향별 실제 값은 전류계로 확인한다.
- 같은 모터와 같은 드라이버 모듈을 1번 채널로 옮겨 `1` 명령으로 같은 시험: RPWM 730mA, LPWM 561mA, 최고 2.37A/1.99A로 2번 채널과 같다. 1번 채널의 PWM, EN, IS 경로와 2.2kΩ이 맞게 동작한다. 기판 두 채널이 같게 읽으므로 RPWM/LPWM 차이는 그 모듈 안에 있다 (모듈의 원래 IS 저항이 남았는지, 칩 차이인지 확인할 것).
- 온도: TEMP 1350mV(11.25mA, 22.7°C), 20초 흔들림 0.03°C. 감지 저항 R26이 지금 5% 1W다 (1% 1W를 못 구함). 설치 때 온도 보정값(`offset`)으로 맞추면 맞춘 온도에서 10°C 떨어져도 오차 약 0.5°C. 1% 1/4W 120Ω 4개 2직렬 2병렬도 대안으로 이야기했다 (문서 R26에 반영할 것).
- 본 펌웨어 `winctrl_bench`(MC 뒤 전압 점검만 끔)를 올렸다. 비상 버튼 없이 J4-1과 J4-2를 선으로 이어 비상정지가 풀렸다 (50W 방식). 처음 켠 보드라 설정이 비어 위치는 `--`, 이동은 받지 않는다 (스펙 8절).
- 1번 창 측정은 `err sensor`로 실패했다. 첫 하강에서 하한(모터 리밋으로 전류 끊김)에 닿았고, 센서 OFF라 "센서 없음"으로 정했는데 HOME TIME이 비어 있어서다 (`calAtBottom`, 스펙대로). 다음: 1번 창 HOME SENS 끔, HOME TIME 입력(책상은 0초), 다시 측정. 2번 창은 드라이버가 없으니 LINK 끔.
- 부팅 로그에 ESP32 코어 3.x 경고가 나온다: pinMode 전 digitalWrite(IO 13, 16, 17, 21), 아날로그 설정 전 `analogSetPinAttenuation`. 동작은 문제없지만 정리할 것.
- 사용자가 정할 것: 드라이버 R_IS/L_IS 차이를 KILIS와 과부하 경계에서 어떻게 다룰지, 62W(약 2.6A) 모터를 50W 모델로 쓸지(문서는 최대 2.4A), R26을 5% 1W + 설치 보정으로 둘지.
- 남은 것: 멀티미터로 모듈 R_IS/L_IS와 GND 사이 저항(원래 저항이 남았는지), 전류계로 `BTS_KILIS`, 온도 반응(손으로 쥐기)과 끊김(선 빼기), 실제 온도계와 비교, MC를 단 뒤 MC 전압과 본 빌드.

실물로 맞춰야 하는 임시 값은 `README.md`의 "실물로 맞춰야 하는 값"에 있다.
